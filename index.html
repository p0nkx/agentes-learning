OpenCode - Comandos y Tutorial

Guía completa de comandos integrados, atajos de teclado y herramientas disponibles.

Como ejecutar comandos

Dentro de la interfaz de OpenCode (TUI), escribe / seguido del nombre del comando. Tambien puedes usar atajos de teclado con ctrl+x como tecla líder (leader key).

# Ejemplo: escribe dentro de OpenCode

/help

# O usa el atajo:

ctrl+x h (si esta configurado)

C Configuración y Modelos

/connect ctrl+x c

Agrega un proveedor de modelos. Te permite seleccionar entre los proveedores disponibles y agregar sus API keys. Para empezar gratis, selecciona "opencode" (Zen).

/models ctrl+x m

Lista los modelos disponibles. Puedes cambiar de modelo en cualquier momento durante la sesión.

/themes ctrl+x t

Lista los temas visuales disponibles. Cambia la apariencia de la interfaz de terminal.

skill (herramienta interna)

Agent Skills - NO es un comando de usuario: Las skills no se ejecutan con /skills. Son comportamientos reutilizables definidos en archivos SKILL.md que los agentes cargan automaticamente bajo demanda.

Como ver las skills disponibles:

  • 1. En terminal, fuera de OpenCode: opencode debug skill (muestra las skills cargadas)
  • 2. Dentro de OpenCode: preguntale: "¿Qué skills tienes disponibles?" - el agente listará nombres y descripciones
  • 3. El agente carga automaticamente una skill cuando detecta que su description coincide con tu tarea

¿Se instalan por proyecto o globalmente?

  • 📁 Global (~/.config/opencode/skills/): Se instalan UNA VEZ y están en TODOS tus proyectos
  • 📂 Por proyecto (.opencode/skills/): Solo para ese proyecto, se pueden compartir con el equipo via Git
  • ⚡ Prioridad: Las skills de proyecto sobrescriben a las globales si tienen el mismo nombre

Dónde buscar nuevas skills:

  • • skills.sh - Directorio de colecciones de skills
  • • openagentskills.dev - Recursos y documentación
  • • GitHub: busca repositorios con archivos SKILL.md

S Sesiones (Espacios de trabajo)

/sessions ctrl+x l

Lista y permite cambiar entre sesiones. Cada sesión es una conversación independiente con su propio historial, pero los cambios en archivos se reflejan en todas.

/new ctrl+x n

Crea una nueva sesión limpia. Alias: /clear.

E Edición y Cambios

/init

Guía paso a paso para crear o actualizar AGENTS.md.

/undo ctrl+x u

Deshace el último mensaje y cambios en archivos. Usa Git internamente.

/redo ctrl+x r

Rehace un mensaje que fue deshecho con /undo.

/compact ctrl+x c

Compacta la sesión actual resumiendo el contexto. Alias: /summarize.

Git - Comandos y Tutorial

Guía esencial de Git para el control de versiones en tus proyectos.

Configuración inicial

Antes de empezar, configura tu identidad en Git:

# Configurar nombre y email (global)

git config --global user.name "Tu Nombre"

git config --global user.email "tu@email.com"

# Ver configuración

git config --list

1 Comandos Básicos

git init

Inicializa un nuevo repositorio Git en el directorio actual.

git clone <url>

Clona un repositorio remoto a tu máquina local.

git status

Muestra el estado actual del repositorio (archivos modificados, staged, etc.).

git log

Muestra el historial de commits del repositorio.

2 Flujo de Trabajo (Staging)

# 1. Agregar archivos al staging area

git add archivo.txt # Agregar un archivo

git add . # Agregar todos los cambios

# 2. Hacer commit

git commit -m "Descripción del cambio"

# 3. Subir cambios al remoto

git push origin main

1

Working Directory: Donde haces cambios en tus archivos

2

Staging Area (Index): Preparas los cambios para el commit con git add

3

Repository: Guardas los cambios definitivamente con git commit

3 Ramas (Branches)

git branch

Lista todas las ramas locales.

git branch -M main

Renombra la rama actual a "main".

git checkout -b feature

Crea y cambia a una nueva rama llamada "feature".

git merge feature

Fusiona la rama "feature" en la rama actual.

4 Repositorios Remotos

# Agregar un repositorio remoto

git remote add origin https://github.com/usuario/repo.git

# Ver remotos configurados

git remote -v

# Subir cambios (push)

git push -u origin main

# Obtener cambios (pull)

git pull origin main

Comandos Git útiles en OpenCode

# Dentro de OpenCode, usa ! para ejecutar comandos

!git status

# Ver diferencias

!git diff

# Ver log resumido

!git log --oneline -10

OpenCode puede ejecutar comandos Git y analizar sus resultados como parte de su flujo de trabajo.

Agent Skills - Guía Completa

Las Skills son comportamientos reutilizables que extienden las capacidades de OpenCode y otros agentes de código AI.

Qué son las Agent Skills

Las Skills son instrucciones declarativas definidas en archivos SKILL.md. No son código ejecutable, son instrucciones Markdown que guían el comportamiento del agente para tareas específicas.

Analogía: Piensa en una Skill como una "receta" que le dices al agente: "Cuando tengas que hacer X tarea, sigue estos pasos específicos".

📁 Estructura de una Skill

Cada Skill vive en su propia carpeta con un archivo SKILL.md:

# Estructura de directorios

mi-skill/

├── SKILL.md # Requerido: nombre, descripción, instrucciones

├── scripts/ # Opcional: código ejecutable

│ └── helper.py

├── references/ # Opcional: documentación

│ └── api-docs.md

└── assets/ # Opcional: plantillas

└── template.html

+ Cómo Crear una Skill

Paso 1: Crear la carpeta y el archivo SKILL.md

# Ejemplo: .opencode/skills/test-generator/SKILL.md

---

name: test-generator

description: Generates unit tests with Jest/Vitest for TypeScript files

license: MIT

compatibility:

- typescript

- javascript

metadata:

author: dev-team

version: 1.0.0

---

# Test Generator Skill

When invoked, follow these steps:

1. Analyze the given TypeScript file

2. Identify all exported functions and classes

3. Generate appropriate unit tests using Jest/Vitest

4. Include edge cases and error handling tests

Paso 2: OpenCode detectará automaticamente la Skill y la listará como disponible.

📂 Dónde instalar Skills

Global (todos los proyectos)

Linux/Mac: ~/.config/opencode/skills/

Windows: C:\Users\elfab\.config\opencode\skills\

Por proyecto (compartido via Git)

En la raíz del proyecto: .opencode/skills/

Se puede commitear a Git para todo el equipo.

Prioridad: Las Skills de proyecto sobrescriben a las globales si tienen el mismo nombre.

Cómo usar Skills en la práctica

1

Automático: Cuando tu solicitud coincide con la descripción de una skill, el agente la carga y aplica sin que se lo pidas.

2

Manual: Puedes invocar una skill por nombre: "Usa la skill de replicate para encontrar un modelo de generación de imágenes".

3

Progressive Disclosure: Al iniciar, OpenCode solo carga el name y description de cada skill. El contenido completo se carga bajo demanda.

Verificar que las skills se cargaron:

# En terminal, fuera de OpenCode:

opencode debug skill

# Dentro de OpenCode:

"¿Qué skills tienes disponibles?"
